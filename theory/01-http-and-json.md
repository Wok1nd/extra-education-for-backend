# 01. HTTP и JSON

Ты уже вызываешь сервер с фронта через `fetch`. Теперь ты этот сервер пишешь. Картинка та же: браузер (или curl) отправляет **запрос**, сервер возвращает **ответ**.

## Из чего состоит запрос

Три части, которые бэкенд всегда смотрит:

1. **Метод** — что клиент хочет сделать. `GET` — прочитать, `POST` — создать, `PATCH` — частично обновить, `DELETE` — удалить.
2. **URL** — к какому ресурсу. Например `/users` или `/users/clxyz123`.
3. **Тело (body)** — данные, если они нужны. У `GET` и `DELETE` тела обычно нет. У `POST` и `PATCH` тело — JSON.

Ответ тоже состоит из частей: **статус-код** (число вроде 200) и **тело** (часто JSON). Статусам посвящён конспект 04.

## JSON

JSON — это текст в строгом формате, который одинаково читают JS на фронте и JS/TS на сервере.

```json
{
  "email": "ada@example.com",
  "name": "Ada"
}
```

На фронте ты делаешь `JSON.stringify` перед `fetch` и `response.json()` после. Fastify сам разбирает JSON-тело, если клиент прислал заголовок `Content-Type: application/json`. Если забудешь заголовок, сервер может увидеть `body` как `undefined` — и вернуть 400, потому что полей нет.

## Endpoint

**Endpoint** — это пара «метод + путь», на которую сервер умеет ответить.

| Endpoint | Смысл |
| --- | --- |
| `GET /health` | Жив ли сервер |
| `GET /users` | Список пользователей |
| `GET /users/:id` | Один пользователь |
| `POST /users` | Создать |
| `PATCH /users/:id` | Обновить поля |
| `DELETE /users/:id` | Удалить |

`:id` — не буквальный текст. Это **параметр пути**: вместо `:id` клиент подставляет конкретный идентификатор.

Два разных метода на одном пути — два разных endpoint. `GET /users` и `POST /users` не путаются.

## Как это выглядит с фронта

```js
await fetch('http://localhost:3000/users', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ email: 'ada@example.com', name: 'Ada' }),
})
```

На бэкенде тот же запрос попадёт в обработчик `POST /users`: метод уже известен, путь совпал, тело лежит в `request.body`.

## Что запомнить

- Сервер не «рисует страницу» — он отвечает на HTTP-запросы данными.
- Метод говорит *действие*, URL — *над чем*, JSON — *с какими данными*.
- CRUD — это просто набор endpoint'ов вокруг одной сущности: Create, Read, Update, Delete.
