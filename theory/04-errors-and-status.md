# 04. Ошибки и статус-коды

Клиенту важно не только тело ответа, но и **число статуса**. Фронт по нему решает: показать данные, форму с ошибкой или «не найдено». Ниже — договорённости этого курса. Они совпадают с типичными REST-критериями (как в задании crud-api у AlreadyBored / RS School): успех, создание, пустое удаление, плохой запрос, нет записи, падение сервера.

## Когда какой код

| Код | Когда | Тело |
| --- | --- | --- |
| **200** | Успешное чтение или обновление: `GET` список, `GET` один, `PATCH` | JSON с данными |
| **201** | Ресурс **создан**: успешный `POST` | JSON новой записи |
| **204** | Ресурс **удалён**: успешный `DELETE` | Пусто, без JSON |
| **400** | Клиент прислал плохие данные: нет обязательных полей | `{ "message": "..." }` |
| **404** | URL понятен, но записи с таким id нет | `{ "message": "..." }` |
| **500** | Упало то, что не должен чинить клиент: баг, база недоступна | `{ "message": "Internal Server Error" }` |

200 — «вот то, что просил». 201 — «вот то, что только что появилось» (часто с новым `id`). 204 — «сделано, смотреть нечего».

## 400 против 404

Путают чаще всего.

- **400** — запрос составлен неправильно. Пример: `POST /users` без `email` или без `name`. Сервер даже не пытается угадать, кого создать.
- **404** — запрос нормальный, но сущности нет. Пример: `GET /users/нет-такого-id`. Id выглядит как строка, просто в таблице пусто.

Не подменяй 404 на 200 с `null`. Фронт тогда не отличит «пользователь есть, имя пустое» от «пользователя нет».

## Как это сделано в User CRUD

Открой `src/modules/users/users.handlers.ts` и сопоставь:

- список и успешный `GET`/`PATCH` → `reply.code(200)`
- `createUser` без полей → `400`
- успешный `POST` → `201`
- нет строки в базе → `404`
- успешный `DELETE` → `204`

В `src/app.ts` стоит `setErrorHandler`: любая необработанная ошибка (например, упала база) уходит как **500**, а не как сырой стектрейс клиенту. Стек остаётся в логе сервера.

## Практическое правило на дне 2

Для Task те же коды:

- `POST /tasks` без `title` или без `userId` → **400**
- `GET`/`PATCH`/`DELETE` с id, которого нет → **404**
- если решишь проверять «существует ли userId» при создании задачи и пользователя нет — это тоже **404** (нет связанной записи) или **400** (некорректная ссылка). Выбери один вариант, опиши его в коде одинаково для всех случаев и не смешивай.

Несуществующий путь вроде `/nope` Fastify сам отвечает 404 — отдельно писать не нужно.

## Что запомнить

- Статус — часть API, не украшение.
- 2xx — получилось, 4xx — ошибка клиента, 5xx — ошибка сервера.
- Перед хакатоном проверь каждый endpoint: и счастливый путь, и «нет id», и «пустое тело».
